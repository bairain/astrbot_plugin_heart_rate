# astrbot_plugin_heart_rate 🫀

AstrBot 插件：通过蓝牙低功耗（BLE）收取标准心率设备（心率带、手环等）的实时心率数据，并在心率超过设定阈值时主动向已绑定的聊天会话发送问候/提醒消息。

> 例如：心率持续高于 100 bpm 时，自动在 QQ/微信等群聊或私聊中发送"当前心率 120 bpm，请放慢节奏、注意休息～"。
>
> 还支持**由 AI 模型按当前人设生成灵活问候**（类似 AstrBot 未来任务）——同一条"心率过高"事件，元气少女会撒娇式催促你休息，严肃助手会给出简短的健康建议。

## ✨ 功能特性

- **两种蓝牙收数模式**：
  - **GATT 连接（默认）**：连接设备并订阅标准心率测量通知（UUID `0x2A37`），最稳定，支持 Polar H10、Wahoo Tickr、CoSpo、小米手环等绝大多数心率设备。
  - **广播被动接收**：不建立连接，直接从 BLE 广播包的 Service Data 中提取心率，适合会在广播中发送心率的设备。
- **自动扫描与连接**：无需手动填写设备地址，可自动搜索广播了心率服务（UUID `0x180D`）的设备；也支持按设备名称关键字过滤。
- **断线自动重连**：连接意外断开后按设定间隔自动重连。
- **阈值主动问候，两种内容模式**：
  - **固定模板**：默认模式，消息模板可自定义，支持 `{hr}`、`{threshold}`、`{device}` 占位符。
  - **🤖 AI 人设生成**：开启后唤醒当前使用的对话模型，结合默认人设为每次告警生成一条符合角色口吻、不重样的主动问候（与 AstrBot 未来任务同一思路）；模型不可用或生成失败时自动回退固定模板。
- **防骚扰机制**：异常持续期间按冷却时间重复提醒；心率回落到阈值 + 恢复余量后才判定"恢复正常"，避免在阈值附近抖动刷屏。
- **会话绑定持久化**：通过 `/hr_bind` 绑定的会话保存在 AstrBot KV 存储中，重启不丢失。
- **模拟测试**：提供 `/hr_test` 指令，无需真实心率设备即可验证告警消息链路（含 AI 生成）。

## 📋 环境要求

| 项目 | 要求 |
| --- | --- |
| AstrBot 版本 | >= 4.16.0 |
| Python | >= 3.10 |
| 蓝牙适配器 | 运行 AstrBot 的机器需具备 BLE（蓝牙低功耗）适配器，Windows 需在系统设置中开启蓝牙 |
| 心率设备 | 支持蓝牙标准心率服务（0x180D）的设备，如 Polar H10、Wahoo Tickr、CoSpo 心率带、部分小米/华为手环等 |

> ⚠️ 蓝牙适配器必须与运行 AstrBot 的机器在同一台设备上。例如 AstrBot 跑在 Windows PC 上，则使用 PC 的蓝牙；若跑在没有蓝牙的服务器上则无法使用。

## 🔧 安装

### 方式一：插件市场（推荐）

在 AstrBot WebUI 的 **插件管理** 页面搜索「心率监测」并安装。安装时 AstrBot 会自动安装 `requirements.txt` 中的依赖（`bleak`）。

### 方式二：手动安装

1. 将本插件目录 `astrbot_plugin_heart_rate` 复制到 AstrBot 的 `data/plugins/` 目录下。
2. 启动 AstrBot，或在 WebUI 插件管理中点击「重载插件」。
3. 首次加载时 AstrBot 会自动执行 `pip install -r requirements.txt` 安装 `bleak`。

## 🚀 快速开始

1. 确保电脑蓝牙已开启，心率设备已开机并佩戴好。
2. 在任意聊天中发送 `/hr_scan`，扫描附近的蓝牙心率设备（建议扫描 10-15 秒）。
3. 在想要接收心率告警的聊天会话中发送 `/hr_bind`，将该会话绑定为告警接收目标。
4. 发送 `/hr_start` 开始监测；如果扫描结果中有多个设备，可指定地址：`/hr_start AA:BB:CC:DD:EE:FF`。
5. 先用 `/hr_test 120` 验证告警消息是否能正常送达；之后 `/hr` 可随时查看实时状态。

## 🤖 AI 人设问候模式（可选）

默认情况下告警发送的是固定模板。开启 AI 模式后，每次心率越界都会像 AstrBot **未来任务**一样唤醒对话模型：把当前默认人设的系统提示词与心率事件任务指令组合，让模型生成一条符合角色口吻的、不重样的问候，再投递到所有已绑定会话。

**开启方式**：在插件配置中把 `use_llm`（由 AI 模型按人设生成问候消息）打开，前提是 AstrBot 已配置至少一个可用的对话模型。

**工作机制**：

1. 心率越过阈值（或恢复正常）触发事件；
2. 插件取当前默认人设（Persona）的系统提示词，追加插件场景约束，再把填好心率数值的任务提示词交给对话模型；
3. 模型输出的文本通过 `send_message` 主动投递到每个已绑定会话；
4. 模型选择：**优先使用当前选中的对话模型**，若该模型调用失败（如接口 404、超时），会自动依次尝试所有已配置的对话模型，直到生成成功；
5. 若所有模型均不可用或返回空内容，自动**回退到固定模板**，不会漏发提醒。

**自定义**：三种场景（过高 / 过低 / 恢复正常）各有独立的任务提示词配置项（`llm_high_prompt`、`llm_low_prompt`、`llm_recovery_prompt`），均支持 `{hr}`、`{threshold}`、`{device}` 占位符，可按自己的人设风格调整；`llm_system_extra` 用于约束模型只输出消息正文。

> 💡 可先用 `/hr_test 120` 在不连接硬件的情况下体验 AI 问候效果。每次生成都是独立的一次性请求（不带历史上下文），消耗 token 很少；并发生成通过锁串行化，不会重复请求模型。

## 💬 指令列表

所有指令均需带 AstrBot 唤醒前缀（默认 `/`）。

| 指令 | 说明 |
| --- | --- |
| `/hr` | 查看监测状态、设备信息、最新心率与当前阈值 |
| `/hr_scan [秒数]` | 扫描附近蓝牙设备，标注是否支持心率服务及广播心率。例：`/hr_scan 10` |
| `/hr_start [设备地址]` | 开始监测。可指定设备 MAC/UUID 地址，留空则自动搜索 |
| `/hr_stop` | 停止监测并断开蓝牙连接 |
| `/hr_bind` | 将当前聊天会话绑定为心率告警接收目标 |
| `/hr_unbind` | 解除当前会话的告警绑定 |
| `/hr_threshold <高> [低]` | 设置阈值。例：`/hr_threshold 100` 或 `/hr_threshold 100 50`；填 `0` 关闭对应提醒 |
| `/hr_test <心率>` | 注入模拟心率用于测试告警链路。例：`/hr_test 120` |

## 🔍 工作模式说明

### GATT 模式（默认，推荐）

标准蓝牙心率服务（HRS）定义了 `0x2A37` 心率测量特征值。设备连接后会周期性地推送通知，通知包的第 0 字节是标志位（bit0 为 0 表示 UINT8 心率，为 1 表示 UINT16 心率），随后是心率值。本插件按此规范解析。

### 广播模式（advertise）

部分设备会在 BLE 广播包的 Service Data（UUID `0x180D`）中直接携带心率测量数据，无需建立连接即可读取。广播模式功耗更低，但并非所有设备都支持（多数手环需要连接后才上报）。

> 不确定设备支持哪种模式时，先用 GATT 模式尝试；如果 `gatt` 模式下连不上，可在 `/hr_scan` 结果中查看设备是否标注了「广播心率」，若是则切换为 `advertise` 模式。

## ❓ 常见问题

**Q：扫描不到设备？**
- 确认设备已开机并进入配对/广播状态（部分设备需要长按按钮进入配对模式）。
- 确认运行 AstrBot 的机器蓝牙已开启，且设备在蓝牙范围内（通常 1-10 米）。
- 尝试延长扫描时间：`/hr_scan 20`。

**Q：连接上但没有心率数据？**
- 部分设备需要先在系统蓝牙中配对后才能连接。
- 尝试切换为 `advertise` 模式。
- 检查设备是否佩戴正确（心率带需接触皮肤、手环需贴紧手腕）。

**Q：Windows 上连接失败 / 报错？**
- 确认 Windows 蓝牙服务已启动。
- 部分 Windows 版本需要先在「设置 → 蓝牙和设备」中手动添加设备。
- bleak 在 Windows 上依赖系统蓝牙栈，不支持虚拟蓝牙适配器。

**Q：为什么没有收到主动告警消息？**
- 确认已发送 `/hr_bind` 绑定会话，且 `/hr` 显示「提醒目标会话」数量大于 0。
- 确认心率确实越过了阈值，可用 `/hr_test 120` 测试。
- 确认 AstrBot 已配置并连接了至少一个消息平台（QQ、微信等）。

**Q：如何修改告警消息内容？**
- 固定模板模式：在 WebUI 插件配置中修改 `high_message`、`low_message`、`recovery_message`，支持 `{hr}`（当前心率）、`{threshold}`（阈值）、`{device}`（设备名）。
- AI 人设模式：打开 `use_llm` 后由对话模型按当前人设生成，可调整 `llm_high_prompt` 等三个场景任务提示词来控制语气与内容。

**Q：开启 AI 模式后会不会因为模型故障收不到提醒？**
- 不会。插件会优先使用当前选中的模型，失败时自动依次尝试所有已配置的对话模型；全部失败（未配置、404、超时、返回空）时回退到 `high_message` 等固定模板并记录 warning 日志，保证提醒必达。
- 日志中会打印每个模型的尝试结果（`AI heart rate greeting trying provider ...`），可据此排查具体是哪个模型服务异常。

**Q：日志里某个模型报 404 但正常聊天没问题？**
- 正常聊天使用的是 WebUI 当前选中的模型（或会话专属路由配置的模型），而早期版本的插件固定取配置中的第一个模型。v1.0.0 起插件会遍历所有模型自动兜底，此问题已解决；也建议在 WebUI 模型配置中修正报 404 的模型服务地址（通常是 `api_base` 缺少 `/v1` 或模型名填写错误）。
